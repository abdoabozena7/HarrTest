## Executed locally

- Baseline suite: 226 tests; 225 passed, one optional browser test skipped.
- Final suite: 258 tests; 257 passed, one optional browser test skipped.
- 32 new checks exercise architecture/host/milestone declarations, omitted root
  requirements, stage ordering, live rather than replay integration, interface
  changes, scope/resource conflict selection, durable resume, repair safeguards,
  fresh-receipt reuse, original-root acceptance and real HTTP service behavior.
- A negative regression first reproduced a repair deadlock: a later change made
  earlier acceptance stale, and admission then prevented the later task repairing
  it. The fix permits an explicitly recorded attempted-task repair, without passing
  any milestone or weakening final acceptance. Unstarted work cannot use this to
  bypass first-time milestone admission.
- The greenfield demo preserves a request in an empty project, creates a runnable
  loopback HTTP service, then catches lost persistence on process restart. After
  implementing persistence it rejects advancement until prior-stage checks rerun
  on current source. It builds a ZIP, launches the unpacked service from a clean
  directory, and checks actual HTTP read/write, rejection of invalid input, and
  restart persistence. A final source edit invalidates prior successful proof.
- Each builder CLI invocation in the demo starts a fresh Python process and
  reconnects to SQLite. The next unfinished milestone is preserved. Once all
  checks are fresh, the check plan reuses all three instead of executing them again.
- No paid model call, extra model client, simulator, cloud service or browser
  dependency is used by these local tests. Compute execution still has normal
  resource cost; the statement is about absent paid model invocations only.

Reproduce with Python 3.10+:

```text
python -B -m unittest discover -s tests -p 'test_*.py' -v
python examples/builder_demo.py --output NEW_DISPOSABLE_DIRECTORY
```

The root fixtures explicitly use legacy self-reviewed coverage. They do not invent
a separate human/agent reviewer. Real deployments retain the existing schema-3
coverage workflow when a genuine separate reviewer is available.

## Not established by these tests

No comparative live Copilot/Codex/Claude model trial, weaker-model improvement,
complete 3D game, visual quality, native CARLA behavior, continuous overnight host
execution, or enterprise security certification was demonstrated. The HTTP example
is a scripted deterministic fixture with author-supplied architecture and code,
not a claim of autonomous AI project generation.

The controller verifies declared plan structure and current acceptance evidence.
It does not choose an objectively best architecture, authenticate all agent claims,
provide OS-level worker isolation, change host permissions, or prove semantic
completeness of the original requirements. A successful helper suite must not be
advertised as a measured improvement in model completion rates.
